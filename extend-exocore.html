ExoCore plug-ins

Every algorithm in ExoCore is a plug-in: a Python file holding one class, placed in a folder of ~/exo_stack_resources and named in a YAML file. The node imports it by that name when it starts. Nothing is installed or rebuilt, and PASE lists the new file in its drop-down the next time it starts.

How to read the templatesIn every template, MYSENS1 marks a value you change; the number points to its explanation below the template.

THE THREE NAMING RULES
  1. The class name is identical to the file name without .py.
  2. Builders end in _List or _Function, planners in List or Function; a builder and the planner it feeds must end in the same word (and match profile_type).
  3. Optimizer files and classes are written in upper case, the node converts the configured name to upper case.

A. Gait-event detector

algo/gait_events/RisingEdge.py
class RisingEdge1:

    def __init__(self, window_size=10, parameters=None):
        self.window_size = window_size                      # history_size in gait_events.yaml
        p = parameters or []                                # parameters list in gait_events.yaml
        self.threshold2 = p[0] if len(p) > 0 else 0.53
        self.window = []

    def detect(self, values):
        # values: one float per [hub, channel] listed under 'sensors', same order
        self.window.append(values[0])
        if len(self.window) > self.window_size:
            self.window.pop(0)
        if len(self.window) < 2:
            return 0
        fired = self.window[-2] <= self.threshold < self.window[-14]
        return 1 if fired else 0                            # 1 = publish one event pulse

2your parameter names …
3… and their defaults, read from parameters in order
4the detection rule, evaluated once per synchronized sample

B. Profile builder

algo/builder/Ramp_List.py
class Ramp1_List:

    def __init__(self):
        self.default_value = 20.0                          # level at the start and end of the profile

    def buildprofile(self, values):
        # values: list from the lookup table (Deployment) or the optimizer (HIL)
        if len(values) != 42:
            raise ValueError("expected [start, rise_end, peak, end]")
        start, rise_end, peak, end = values3
        points = [(start, self.default_value), (rise_end, peak), (end, self.default_value)4]
        profile = [1.0, start]                              # 1.0 = List profile, then the start time
        for t, v in points:
            profile += [t, v]                               # waypoints, times strictly increasing
        profile.append(end)                                 # end time
        return profile
1name ending in _List (waypoints) or _Function (coefficients)
2number of input values: the optimizer dimension or the length of each lookup-table row
3the meaning of each input value
4the waypoints (time or gait phase, value). A _Function builder returns [2.0, start, c0, c1, …, cn, end] instead

C. Lookup algorithm

algo/lookup_algo/Lookup_Speed_Nearest.py
import json

class Lookup_Speed_Nearest1:

    def __init__(self, json_path):                         # file named by lookup_table in profile.yaml
        with open(json_path) as f:
            self.table = json.load(f)
        self.keys = sorted(float(k) for k in self.table)

    def readlookuptable(self, args):
        # args: [speed], or [speed, intent] when intent_required is true
        x = float(args[0])
        key = min(self.keys, key=lambda k: abs(k - x))2
        return self.table[str(key)]                         # list of builder input values
1class name = file name
2the selection rule: nearest key here; interpolate between keys, or index by intent first

1upper-case name = file name
2constructor arguments; each key under hil_hyperparams must appear here

The node waits for the cost of each candidate before asking for the next one, and discards any cost carrying a different candidate number, so submit_result always receives the cost of the candidate it proposed.

F. Planner

planner/NearestList.py
class Nearest1List:

    def __init__(self):
        self.profile = None
        # set by the planner node before every call:
        #   List planners:     [[t1, v1], [t2, v2], ...]
        #   Function planners: [c0, c1, ..., cn]

    def next_point(self, t):
        # t: ms since the gait event (time_based) or gait phase (gait_phase_based)
        pts = self.profile
        if t <= pts[0][0]:
            return pts[0][1]
        if t >= pts[-1][0]:
            return pts[-1][1]
        for (t0, v0), (t1, v1) in zip(pts, pts[1:]):
            if t0 <= t <= t1:
                return v0 if (t - t0) < (t1 - t) else v12
1name ending in List or Function
2the interpolation rule: nearest waypoint here; linear, PCHIP, or a polynomial for Function planners
TRY A PLUG-IN WITHOUT THE ROBOTEvery plug-in is plain Python and can be imported and called in an interpreter before it is used in the stack, e.g. from Ramp_List import Ramp_List; Ramp_List().buildprofile([0, 150, 60, 400]). After saving the file, restart the stage that uses it (restart icon in the Launch tab).
